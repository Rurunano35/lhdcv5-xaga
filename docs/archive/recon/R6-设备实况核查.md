1. **协议栈侧齐备**：`libbluetooth_jni.so` 内含 AIDL V5 客户端代码（`a2dp_encoding_aidl.cc` 字符串 ×2、`Lhdcv5Configuration` ×4、`A2dpLhdcv5ToHalConfig` ×3）。
2. **接口定义齐备**：APEX 内 `vendor.mediatek.hardware.bluetooth.audio-V1-ndk.so` 带完整 `Lhdcv5Configuration` / `Lhdcv5Capabilities` parcelable。
3. **服务端完全缺失**：
   - `lshal` 无任何 AIDL bluetooth audio 服务；
   - `service list` 无 `...IBluetoothAudioProviderFactory`；
   - `/vendor/etc/vintf/manifest.xml` 零 `format="aidl"`；
   - `/vendor/bin/hw/` 无 AIDL 实现可执行文件；
   - 全 `/vendor` 分区 grep 无 `vendor.mediatek.hardware.bluetooth.audio.IBluetoothAudioProviderFactory` 的实现。
4. **HIDL 实现确实无 V5 结构**：`vendor.mediatek.hardware.bluetooth.audio@2.2-impl.so` 与 `@2.1-impl.so` 中 `Lhdcv5` 计数为 0，只有 `lhdcConfig`。
5. **栈的选路逻辑会优先 AIDL**：`hal_version_manager.cc` 先打印 aidl 再打印 hidl，说明一旦 AIDL 服务可用，栈会尝试走它。

### 因此，打通 V5（不伪装）的**必要前置条件**为

| # | 前置条件 | 当前状态 | 缺口性质 |
|---|---|---|---|
| **C1** | 存在一个实现 `vendor.mediatek.hardware.bluetooth.audio.IBluetoothAudioProviderFactory` 的 **AIDL HAL 服务进程** | ❌ 完全不存在 | **必须自行实现**（HAL 服务端） |
| **C2** | 该实现支持 `Lhdcv5Configuration` 的 `startSession` / `parseAudioConfig` / PCM 输入通路 | ❌ 无 | **必须自行实现** |
| **C3** | 该服务在 servicemanager 注册为 `vendor.mediatek.hardware.bluetooth.audio.IBluetoothAudioProviderFactory/default` | ❌ | init rc + 注册代码 |
| **C4** | `/vendor/etc/vintf/manifest.xml` 增加对应 `<hal format="aidl">` 声明 | ❌ 零 AIDL 条目 | 修改 vendor 分区（需绕过 AVB 或 systemless 挂载） |
| **C5** | 该实现被 `HalVersionManager` 选中（先 AIDL 后 HIDL 的选路） | ⚠️ 逻辑已在，但 C1–C4 不满足 | 依赖 C1–C4 |
| **C6** | 编码器库 `liblhdcv5.so` + `liblhdcv5BT_enc.so` | ✅ 已在 APEX，字节完整 | 无缺口 |
| **C7** | CPU 算力 | ✅ 历史实测 `lhdcv5BT_init_encoder: success!` | 无缺口 |

> **与报告 §6「理论上可修，实践上不可修」的关系**：
> R6 的实测把「不可修」精确化为 **C1–C4 缺一个 HAL 服务端实现**，而不是「接口代次断层」。
> 接口（`Lhdcv5Configuration`）与客户端（协议栈 AIDL 代码）**都已存在**；
> 缺的是**服务端**——需要自己写一个 AIDL HAL 进程并复刻整个 BT audio session / PCM 通路。
> 这是「可写但工作量与风险极大」，而非「无源码故不可能」。
> 最终可行性判断超出 R6 范围，需由后续 R 编号任务（HAL 实现可行性）定论。
